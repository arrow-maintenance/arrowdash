* **Windows on ARM support:** Microsoft engineers proposed a support plan for `win_arm64` wheels for PyArrow, offering engineering resources to implement abi3 and unified Windows build paths. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSPythonCI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **ADBC 24 release:** The community approved the release of ADBC 24, which includes 55 resolved issues and critical fixes for Windows JNI artifacts. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Concurrent PR limits:** Discussion on limiting the number of open pull requests for non-committers to improve repository hygiene and mitigate an influx of stale or low-value contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **BigDecimal extension type:** Formal proposal for an `arrow.big_decimal` canonical extension type to support high-fidelity transport for variable-scale numeric data from systems like PostgreSQL and Trino. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTEFormat%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Variant and Parquet spec alignment:** Proposal to modify the Arrow Variant extension specification to ensure full compatibility with the Parquet shredding spec, specifically regarding the representation of unsigned integers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Swift 6.0 minimum version:** Proposal to raise the minimum Swift version to 6.0 to leverage native `Int128` types, which are essential for implementing high-precision Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSSwift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Arrow 25.0.1 release:** Completion of the 25.0.1 patch release, addressing 9 issues including critical performance improvements for nested type conversions in PyArrow. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Nested field nullability semantics:** Technical discussion regarding the logical consistency of struct validity masks and the interaction between parent and child nullability in complex hierarchies. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)
