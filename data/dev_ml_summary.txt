* **Windows ARM64 support for PyArrow:** Microsoft proposed a plan to support `win_arm64` wheels, offering engineering resources for triage and hardware for maintainers, contingent on adopting `abi3` wheels and a unified Windows build path. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSPythonCI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Limiting concurrent PRs for non-committers:** Discussion on limiting contributors without write access to 3 concurrent open pull requests to mitigate the impact of stale or AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Deprecation of Tensor and SparseTensor in IPC:** Formal vote to informally deprecate Tensor and SparseTensor messages in the IPC protocol, as they lack cross-implementation support and the C++ implementation is the only complete one. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Informal%20deprecation%20of%20Tensor%20and%20SparseTensor%20in%20IPC)

* **Canonical Extension Type for FILE:** Proposal to introduce an `arrow.parquet.file` extension type to provide an in-memory Arrow representation for the Parquet FILE LogicalType, facilitating better transport of file-level references. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **BigDecimal Extension Type proposal:** A vote on a canonical BigDecimal extension type for high-fidelity RDBMS numeric transport was paused to gather more information on ecosystem requirements for compute kernel support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTEFormat%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **ArxLang introduction:** Introduction of Arx, an experimental programming language designed to use Apache Arrow as the native foundation for its data-oriented runtime and types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Variant extension and Parquet consistency:** Discussion on modifying the Arrow Variant extension specification to explicitly disallow certain types, such as unsigned integers, to ensure consistency with the Parquet shredding specification. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Lazy memory mapping for Parquet:** Exploration of using custom fault handling to lazily map Parquet columns into memory, allowing developers to perform vectorized operations over entire columns without explicit row-group management. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSParquetCPython%20Lazy%20memory%20mapping)

* **Arrow 25.0.1 release:** The community approved and released version 25.0.1, a patch release resolving nine issues including performance improvements for nested type conversions in Python. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2025.0.1%20released)

* **Revitalizing Conbench benchmarking:** Discussion on moving the Conbench project toward a new architecture using Parquet and DuckDB for storage and querying to improve performance and usability for Arrow project benchmarks. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Status%20of%20Arrow%20conbench%20data%20%2B%20conbench%20OSS%20project)
