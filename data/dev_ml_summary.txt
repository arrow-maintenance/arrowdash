* **Apache Arrow 25.0.1 release:** The community released version 25.0.1, a patch release addressing 9 issues including significant performance improvements for nested type conversions in Python. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2025.0.1%20released)

* **Windows on Arm support for PyArrow:** Microsoft and Linaro proposed a commitment to provide engineering resources and hardware to support win_arm64 builds, aiming to consolidate Windows build paths and implement abi3 wheels. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Canonical BigDecimal extension type:** Discussion and a preliminary vote were held for a new `arrow.big_decimal` extension type to better represent variable-scale numeric data from RDBMSs like PostgreSQL and Trino. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Limits on concurrent open PRs:** To manage an increase in low-value and potentially AI-generated contributions, the community discussed limiting non-committers to three concurrent open pull requests. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **ArxLang introduction:** Developers introduced Arx, an experimental programming language that uses Apache Arrow as its native foundation for arrays, tensors, and DataFrames. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Release of nanoarrow 0.9.0:** The nanoarrow sub-project released version 0.9.0, featuring 38 resolved issues and improved integration with the Arrow C Data interface. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)

* **Variant and Parquet spec alignment:** Technical discussion focused on resolving inconsistencies between the Variant extension specification and the Parquet shredding specification regarding unsupported types like unsigned integers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Lazy memory mapping for Parquet:** A proposal was introduced to use custom fault handling to map Parquet column address ranges lazily, enabling zero-copy NumPy access to entire columns without explicit row-group handling. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Parquet%20C%20Python%20Lazy%20memory%20mapping)

* **Community recognition:** The project welcomed Jeffrey Vo as a new PMC member, and Tadeja Kadunc and Zehua Zou as new committers across the C++ and CI domains. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20New%20Arrow%20PMC%20member%20Jeffrey%20Vo%20%28Jefffrey%29)
