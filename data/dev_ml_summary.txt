* **Windows on Arm support:** Microsoft and Linaro proposed a plan to provide engineering resources and hardware to support win_arm64 wheels for PyArrow, contingent on moving to the stable ABI (abi3). [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Limits on concurrent pull requests:** Discussion is underway to limit non-committers to three concurrent open pull requests to help manage stale contributions and mitigate a surge in low-quality AI-generated PRs. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Canonical BigDecimal extension type:** A proposal to add a variable-scale decimal type for better RDBMS interoperability faced questions regarding its memory layout and whether it should be optimized for computation or just transport. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Apache Arrow 25.0.1 release:** A patch release was finalized to address nine issues, including critical fixes for Gandiva timezone handling and nested type conversion performance. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **ArxLang introduction:** Developers presented Arx, an experimental programming language that uses Apache Arrow C++ as its native foundation for arrays, tensors, and DataFrames. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Variant and Parquet shredding consistency:** Community members are working to reconcile the Arrow Variant extension specification with the Parquet shredding spec, specifically regarding the handling of unsigned integers and null values. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Lazy memory mapping for Parquet:** A new proposal explores using page fault handling to lazily map Parquet columns into NumPy-like arrays, hiding row-group boundaries from the end user. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Parquet%20C%20Python%20Lazy%20memory%20mapping)

* **Subproject updates:** Successful releases were announced for several subprojects, including ADBC 24, nanoarrow 0.9.0, and Apache Arrow Rust 59.2.0. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20ADBC%2024%20Released)

* **Community growth:** The project welcomed Jeffrey Vo as a new PMC member, along with Tadeja Kadunc and Zehua Zou as new committers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20New%20Arrow%20PMC%20member%20Jeffrey%20Vo%20Jefffrey)

* **Swift 6.0 upgrade:** A proposal was made to raise the minimum supported Swift version to 6.0 for the Arrow Swift implementation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)
