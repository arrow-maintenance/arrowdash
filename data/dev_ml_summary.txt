* **Windows Arm64 support for PyArrow:** Microsoft proposed a plan to add `win_arm64` build support, offering dedicated engineering resources and hardware to the community to ensure long-term platform maintenance. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Apache Arrow 25.0.1 release:** The community approved and released version 25.0.1, a patch release resolving nine issues and providing significant performance boosts for nested type conversions in Python. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Limiting concurrent PRs for non-committers:** To manage an uptick in low-value and AI-generated contributions, developers discussed a policy to limit non-committers to three concurrent open pull requests. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **BigDecimal Canonical Extension Type:** A proposal for a `BigDecimal` extension type to handle variable-scale decimals was discussed and eventually paused to better align with broader ecosystem requirements and compute kernel support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Deprecation of Tensor and SparseTensor IPC messages:** A vote passed to informally deprecate Tensor and SparseTensor messages in the IPC protocol due to a lack of multi-language implementation and maintenance. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Informal%20deprecation%20of%20Tensor%20and%20SparseTensor%20in%20IPC)

* **Canonical Extension Type for FILE:** Discussion is underway to introduce an `arrow.parquet.file` extension type to represent file-level references, mirroring the recently added FILE logical type in the Parquet specification. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **ArxLang introduction:** Developers introduced Arx, an experimental programming language designed to use Apache Arrow as its native foundation for data-oriented runtime and data types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **NumPy 2.0 requirement:** A proposal was made to require NumPy 2.0 or newer in upcoming Arrow releases to support new features like variable-width string data conversions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)

* **Variant extension and Parquet shredding alignment:** The community is discussing refinements to the Arrow Variant extension type to ensure strict compatibility with the Parquet shredding specification regarding unsigned integers and null values. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)
