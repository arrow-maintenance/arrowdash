* **Apache Arrow 25.0.0 and 25.0.1 releases:** Arrow 25.0.0 was released with 222 resolved issues, followed quickly by a 25.0.1 patch release to address regressions in nested type performance and Spark compatibility. [Thread 25.0.0](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.0%20-%20RC1) [Thread 25.0.1](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Windows ARM64 support for PyArrow:** Microsoft and Linaro proposed a plan to enable `win_arm64` wheels for PyArrow, involving a transition to `abi3` to manage project size and a commitment to hardware and engineering resources. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **ADBC 24 release and documentation overhaul:** The Arrow Database Connectivity (ADBC) subproject released version 24 alongside a major documentation rewrite designed to clarify the distinction between ASF-maintained and vendor-maintained drivers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Swift 6.0 minimum version proposal:** Discussion on raising the minimum Swift version requirement to 6.0 to leverage native `Int128` support, which is necessary for implementing robust Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Semantics of non-nullable fields:** A deep dive into the interpretation of the `nullable` flag in the IPC format, particularly how it affects complex types like nested structs and dictionary arrays. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **NumPy 2.0 requirement for PyArrow:** Proposal to require NumPy 2.0 or newer for the next major Arrow release to support new variable-width string types and simplify the dependency matrix. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)

* **Parquet extended range timestamp type:** Coordination with the Parquet community on a proposal to support the full SQL range for nanosecond-precision timestamps. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:FYI%20Parquet%20proposal%20for%20extended%20range%20timestamp%20type)

* **nanoarrow 0.9.0 release candidate:** The lightweight nanoarrow implementation is nearing its 0.9.0 release, introducing numerous bug fixes and feature enhancements across C, C++, Python, and R. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)
