* **Arrow 26.0.0 release:** The community approved the release of version 26.0.0, which resolves over 330 issues across the C++, Python, and core implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%2026.0.0%20-%20RC0)

* **Arrow Rust 60.0.0 release:** The latest major release of the Rust implementation includes updated Parquet encoding support, kernel performance improvements, and ongoing work to reduce panics. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Arrow%20Rust%2060.0.0)

* **Improving PyArrow modularity:** Proposal to split PyArrow into smaller, optional wheels (e.g., `pyarrow-s3`, `pyarrow-flight`) to reduce the installation size and maintenance burden on PyPI. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Improve%20modularity%20of%20PyArrow)

* **Dropping macOS Intel support:** Discussion on phasing out support for Intel-based macOS in CI following Homebrew's decision to stop providing Intel bottles and the transition to ARM-based hardware. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Drop%20macOS%20Intel%20support)

* **AI-generated contribution guidelines:** Proposed policies for reviewers to handle low-quality AI-generated pull requests, including a new "needs-author-engagement" label for flagging PRs with weak author interaction. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:AI-generated%20contributions)

* **Canonical range extension types:** A vote is underway to add `arrow.fixed_closedness_range` and `arrow.variable_closedness_range` as canonical extension types for representing mathematical intervals. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Fixed%20and%20variable%20closedness%20range%20canonical%20extension%20types)

* **ADBC visual identity:** The community has reached lazy consensus on a new logo and visual identity for the Arrow Database Connectivity (ADBC) subproject. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ADBC%20Logo%20Proposal)

* **Dictionary-encoded extension types:** Discussion on updating the IPC format to allow custom metadata on dictionary value types, enabling better support for complex extension types like UUIDs when they are dictionary-encoded. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:IPC%20representation%20of%20dictionary-encoded%20extension%20types)
