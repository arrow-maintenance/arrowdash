* **Windows Arm64 Support:** Microsoft engineers proposed a detailed support plan for `win_arm64` wheels in PyArrow, including dedicated maintenance from Linaro and hardware for maintainers to help stabilize CI. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **BigDecimal Extension Type:** A proposal for a canonical `arrow.big_decimal` type to improve RDBMS interoperability was discussed but ultimately paused to better define requirements for compute kernel support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **PR Limits for Non-Committers:** To address a rise in stale and AI-generated contributions, the community is considering a limit of three concurrent open pull requests for contributors without write access. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Deprecating Tensor IPC Messages:** Developers are discussing the formal deprecation of Tensor and SparseTensor IPC messages, noting that these features lack cross-language implementation beyond C++. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Discuss%20IPC%20Deprecate%20Tensor%20and%20SparseTensor%20messages)

* **Variant and Parquet Alignment:** Discussion is underway to align the Arrow Variant extension spec with the Parquet shredding spec, specifically by disallowing types in shredded columns that lack a Variant equivalent. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Lazy Memory Mapping for Parquet:** A new library proposal suggests using custom fault handling to enable lazy, zero-copy loading of Parquet columns as NumPy arrays, hiding row-group boundaries from the user. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Parquet%20C%20Python%20Lazy%20memory%20mapping)

* **Community Appointments and Releases:** The project announced several new maintainers including PMC member Jeffrey Vo and committers Tadeja Kadunc and Zehua Zou, alongside the release of nanoarrow 0.9.0 and Arrow Rust 59.3.0. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20New%20Arrow%20PMC%20member%20Jeffrey%20Vo%20Jefffrey)

* **NumPy 2.0 Transition:** A proposal was raised to potentially require NumPy 2.0 or newer in future Arrow releases to support better conversion of variable-width string data. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)

* **Community over Code Hackathon:** Planning is underway for an Arrow hackathon in Glasgow this October, with a call for curated "good first issues" and task lists to engage new contributors. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Arrow%20Hackathon%20at%20Community%20Over%20Code%20Conference%202026)
