* **Apache Arrow 26.0.0 release:** This major release resolves over 330 issues across the C++, Python, and R implementations, featuring a wide range of performance improvements and bug fixes. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2026.0.0%20released)

* **PyArrow modularity and wheel size:** A proof-of-concept was presented to split PyArrow into multiple optional wheels (e.g., `pyarrow-s3`) to reduce the standard installation size from its current 2.1GB footprint. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Improve%20modularity%20of%20PyArrow)

* **Arrow Rust 60.0.0 release:** The Rust community announced a new major version including new Parquet encoding support, kernel performance optimizations, and significant work to remove panics from the codebase. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUCNCE%20Arrow%20Rust%2060.0.0)

* **GitHub Actions CI optimization:** Maintainers discussed strategies to reduce GitHub runner minutes by up to 40% through label-based triggers, using `ubuntu-slim` runners, and batching expensive packaging jobs for nightly runs. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Ideas%20to%20make%20Arrow's%20GitHub%20Actions%20CI%20lighter%20%7E30-40%25%20fewer%20runner%20minutes)

* **New canonical range extension types:** A proposal and vote are underway to add fixed and variable closedness range types to the Arrow specification to standardize the representation of mathematical intervals. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Fixed%20and%20variable%20closedness%20range%20canonical%20extension%20types)

* **IPC support for dictionary-encoded extension types:** Developers are working to allow `custom_metadata` on dictionary value types within the IPC format, which currently prevents extension type metadata from being preserved during dictionary encoding. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:IPC%20representation%20of%20dictionary-encoded%20extension%20types)

* **IBM Db2 ADBC driver contribution:** IBM proposed contributing a native C++ ADBC driver for Db2 (LUW) to the project, expanding the ecosystem of high-performance database drivers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Request%20to%20contribute%20IBM%20Db2%20driver%20to%20arrow-adbc)

* **Flight SQL Substrait dialect discovery:** A proposal to add new `SqlInfo` codes would allow Flight SQL servers to advertise which Substrait dialects and function sets they support for better plan compatibility. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20FlightSQL%20Advertise%20supported%20Substrait%20dialect%20via%20SqlInfo)
