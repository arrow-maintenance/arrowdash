* **AI-generated contributions:** Nic Crane's impact review proposed a PR cap, mandatory AI-use disclosure with a bot that converts non-compliant PRs to drafts, and a neutral "needs-author-engagement" label. Participants favored giving authors a chance to respond before closing. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20AI-generated%20contributions)

* **Arrow 26.0.1 patch release:** The RC1 vote passed with seven binding +1s, and the release was announced on November 4. It includes the Brotli fix for CVE-2026-111497 (GH-55165). [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2026.0.1%20-%20RC1) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2026.0.1%20released)

* **Arrow Java 20.0.0 and release cadence:** Java 20.0.0 passed its vote and was released on November 21, with Java 17 now the minimum. A proposal to release Arrow Java at least quarterly, or on demand, received support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Arrow%20Java%20regular%20release%20cadence) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20Java%2020.0.0%20Released)

* **Arrow Rust patch releases:** Rust 60.2.0, 59.3.3, 58.4.2 and 57.3.3 all passed their votes in November. Some release notes flag minor non-blocking items, such as license-file clarifications for copied code. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2060.2.0%20RC1) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2059.3.3%20RC1)

* **pull_request_target restriction:** GitHub will restrict the pull_request_target trigger from December 2, with brownouts in November. Arrow is tracking the workflows that need migrating, and a Boring Cyborg labeling bot was enabled across the Arrow repos. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:pull_request_target%20trigger%20migration)

* **Copilot auto-review billing:** Automatic Copilot reviews on every push were being billed to contributors' personal accounts. A change to stop automatic review on pushes was proposed to merge on November 24. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Auto%20GitHub%20Copilot%20review)

* **Sovereign Tech Fund backs PyArrow:** The German Sovereign Tech Agency will fund about 1.9 FTE of PyArrow work through 2027. Priorities include type annotations, the old issue backlog, tooling for AI contributions, and documentation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Announce%20The%20Sovereign%20Tech%20Fund%20invests%20in%20PyArrow)

* **FILE canonical extension type:** A vote is open on adding arrow.parquet.file as a canonical extension type that matches the Parquet FILE logical type. Some members argued Parquet should define its own extension types, while others favored canonical Arrow definitions for consistency across bindings. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Add%20arrow.parquet.file%20canonical%20extension%20type%20%28GH-51143%29) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **Flight SQL Substrait dialect codes:** A vote proposes two new SqlInfo codes that describe which Substrait dialect a server accepts, plus a hash for client caching. The change is backward-compatible and has gathered several binding +1 votes. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20FlightSQL%20Add%20Substrait%20dialect%20SqlInfo%20codes)

* **ADBC 1.2 planning:** A November 24 session set the 1.2 direction. Async is out of scope, metadata and credential callbacks are being refined, and vendor actions will serve as the escape hatch. Partitioned bulk ingest still lacks consensus. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ADBC%20specification%20version%201.2%20planning%20session%20November%2024%2023:00%20UTC)
