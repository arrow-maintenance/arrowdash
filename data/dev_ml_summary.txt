* **JSON representation of Arrow schemas:** Discussion regarding the lack of a canonical human-readable schema representation for use in JSON APIs and metadata. Contributors are debating the balance between human-readability (e.g., "uint32") and strict machine-parity with Flatbuffer structures. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20JSON%20representation%20of%20Arrow%20schemas)

* **Release of Apache Arrow 25.0.0:** The project finalized the 25.0.0 release, resolving over 220 issues. A proposed performance optimization for `to_pylist` in PyArrow was discussed but deferred to a future patch release to ensure thorough review. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **ADBC 24 release and documentation overhaul:** Release 24 of the Arrow Database Connectivity (ADBC) subproject was completed, featuring a major overhaul of the documentation site. The updates help clarify the ecosystem of drivers, many of which are now maintained by external vendors. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Semantics of non-nullable nested fields:** A technical discussion explores the meaning of the `nullable` flag in IPC for complex types like structs. Developers are addressing how to handle non-nullable child fields when the parent container itself contains nulls. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Swift 6.0 minimum version proposal:** Proposal to raise the minimum requirement for the Swift implementation to version 6.0. This change would leverage native `Int128` support, which is a prerequisite for robustly implementing Decimal32 through Decimal256 types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSSwift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Variant extension and Parquet shredding inconsistency:** Reviewers identified a discrepancy between the Arrow Variant extension spec and the Parquet Variant shredding spec. A proposal was made to align the allowed primitive types to ensure data can round-trip correctly between the two formats. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Field name constraints in C Data Interface:** Fuzz testing revealed edge cases regarding nul bytes in field names within the C FFI. The consensus is that producers should detect and error out on embedded nul bytes to prevent issues with C-style string handling. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **Parquet extended range timestamp proposal:** Community members are tracking a Parquet proposal to support the full SQL range for nanosecond-level timestamps. This would allow better interoperability for high-precision time data between Arrow and Parquet. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:FYI%20Parquet%20proposal%20for%20extended%20range%20timestamp%20type)
