* **Windows Arm64 support:** Microsoft proposed a plan to bring official win_arm64 support to PyArrow, including dedicated engineering resources for CI maintenance and hardware for core maintainers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Limits on concurrent open PRs:** Proposal to limit non-committers to three concurrent open pull requests to mitigate an uptick in low-quality or AI-generated contributions that often go stale. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Arrow 25.0.1 and Rust releases:** The community successfully released Apache Arrow 25.0.1, nanoarrow 0.9.0, and multiple updates to the Rust implementation (versions 59.2.0 and 59.3.0). [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **BigDecimal extension type status:** A proposal for a canonical BigDecimal extension type was paused to re-evaluate ecosystem requirements, specifically concerning compute kernel support and RDBMS interoperability. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Variant spec alignment:** Discussion on aligning the Arrow Variant extension specification with Parquet shredding by disallowing types that lack a direct equivalent in the Variant format. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **ArxLang introduction:** Developers introduced Arx, an experimental programming language that uses Apache Arrow as its native foundation for data-oriented runtimes and types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Lazy memory mapping for Parquet:** Exploration of using custom fault handling to lazily map Parquet columns into memory, hiding row-group boundaries from the caller while retaining lazy-loading benefits. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Lazy%20memory%20mapping)

* **New maintainers:** Jeffrey Vo was appointed to the Project Management Committee (PMC), and Tadeja Kadunc and Zehua Zou were welcomed as new project committers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:New%20Arrow%20PMC%20member%20Jeffrey%20Vo%20Jefffrey)
