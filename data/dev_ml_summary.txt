* **Nested struct nullability semantics:** Discussion on avoiding dummy values in non-nullable child arrays of structs by using a positional "take" index to map parent rows to child data. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Apache Arrow ADBC 24 release:** The community released version 24 of the Arrow Database Connectivity (ADBC) libraries, featuring significant bug fixes across C++, Go, Java, and Python. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Windows Arm64 support for PyArrow:** Microsoft and Linaro proposed a commitment to support Windows on Arm (win_arm64), offering funded engineering time and hardware for maintainers to ensure stable CI and official wheels. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Variant and Parquet spec synchronization:** Proposal to align the Arrow Variant extension specification with Parquet's shredding spec to resolve inconsistencies regarding unsigned integer and null type representations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Swift 6.0 upgrade:** Discussion on raising the minimum required Swift version to 6.0 to leverage native Int128 support for high-precision decimal implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Limit on concurrent PRs for non-committers:** Proposal to implement a limit of three concurrent open pull requests for non-committers to manage the influx of stale contributions and AI-generated spam. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **BigDecimal canonical extension type:** A formal vote was opened for a new extension type to represent variable-scale numeric data, though some members suggested more discussion is needed on the underlying representation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Apache Arrow 25.0.1 patch release:** A maintenance release was finalized to address critical bugs and performance regressions discovered following the major 25.0.0 release. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%2025.0.1%20-%20RC1)
