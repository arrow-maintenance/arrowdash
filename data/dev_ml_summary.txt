* **Windows on Arm support for PyArrow:** Microsoft and Linaro proposed a plan to support Windows on Arm (win_arm64), offering to maintain abi3 wheels and a unified Windows build path. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Limit on concurrent open PRs:** Proposal to limit non-committers to 3 concurrent open pull requests to help manage stale PRs and low-value AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Proposal for Canonical BigDecimal Extension Type:** Discussion on a new extension type to support variable-scale numeric data, improving compatibility with database types like PostgreSQL NUMERIC. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Raising minimum Swift version to 6.0:** Proposal to bump the Swift requirement to 6.0 to utilize native Int128 support for high-precision decimal arithmetic. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Apache Arrow 25.0.1 release:** A patch release was finalized, addressing issues in nested type conversion in PyArrow and time zone handling in Gandiva. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Variant spec alignment with Parquet:** Discussion on refining the Arrow Variant extension specification to resolve inconsistencies with Parquet shredding, specifically regarding unsigned integers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **ArxLang: Arrow-native programming language:** Introduction of Arx, an experimental language that uses Apache Arrow as its native foundation for data types and its runtime. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Requiring NumPy 2.0+ for PyArrow:** Proposal to set NumPy 2.0 as the minimum version in the next release to support native variable-width string conversion. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)

* **Subproject Releases (ADBC 24 and nanoarrow 0.9.0):** Successful releases of the ADBC database abstraction layer and the nanoarrow C library implementation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)
