* **Apache Arrow 25.0.0 Release:** The community released version 25.0.0 with 220+ resolved issues, choosing to proceed with the release candidate while planning a subsequent patch to address a specific PyArrow performance regression impacting Spark 4.2 users. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **JSON representation of Arrow schemas:** Discussion on a proposed JSON specification for Arrow schemas to facilitate easier use in REST APIs and ADBC, with debate focused on balancing human readability against strict Flatbuffer alignment. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20JSON%20representation%20of%20Arrow%20schemas)

* **Semantics of non-nullable fields in nested types:** A technical deep-dive into how the `nullable` flag should be interpreted for complex types like structs and unions, including proposals for new indexing methods to handle sparse data without dummy value injection. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Swift 6.0 minimum version proposal:** Proposal to raise the minimum supported Swift version to 6.0 to leverage native `Int128` support, which is essential for implementing Decimal32/64/128 types in the Swift implementation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **ADBC 24 Release and Documentation:** The community released version 24 of the Arrow Database Connectivity (ADBC) libraries and launched an overhauled documentation site to better distinguish between ASF-maintained and vendor-provided drivers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Variant extension spec inconsistency:** Developers identified discrepancies between Arrow's Variant extension and Parquet's shredding specification regarding unsigned integers, leading to a proposal to align Arrow's implementation with the Parquet standard. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **C Data Interface field name safety:** Clarification that the C FFI should explicitly error out when field names contain embedded null bytes, ensuring consistency between IPC and C FFI round-tripping and preventing potential security or stability issues. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **Nanoarrow 0.9.0 release:** Proposal and vote for the 0.9.0 release of nanoarrow, which includes 38 resolved issues and improved integration for lightweight Arrow usage. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)

* **Extended range timestamp proposal:** Community notification of a Parquet-level proposal to support the full SQL range for nanosecond timestamps, which may have future implications for Arrow's timestamp handling. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:FYI%20Parquet%20proposal%20for%20extended%20range%20timestamp%20type)
