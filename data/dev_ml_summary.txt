* **Release wave (Arrow 25.0.1, nanoarrow 0.9.0, ADBC 24, and more):** A busy month of releases across the ecosystem, including the Arrow 25.0.1 patch which notably improved `to_pylist()` performance for nested types by up to 10x. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Semantics of non-nullable fields in complex types:** Developers are discussing the exact meaning of the `nullable` flag in IPC for nested types, such as how to handle non-nullable children within a null parent struct or null values within dictionary indices. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Windows ARM64 support for PyArrow:** Microsoft and Linaro proposed a plan to enable Windows ARM64 CI and wheels, including a commitment to consolidate Windows build paths and adopt ABI3 to mitigate PyPI storage concerns. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Canonical BigDecimal extension type:** Proposal to add `arrow.big_decimal` as a canonical extension type to support variable-scale decimal data commonly found in databases like PostgreSQL and Trino. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Variant specification inconsistencies:** A technical audit revealed discrepancies between the Arrow Variant extension and the Parquet Shredding specification, particularly regarding the support for unsigned integer types in shredded columns. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Limiting concurrent PRs for non-committers:** To combat a rise in stale and AI-generated contributions, the community is discussing a policy to limit contributors without write access to a maximum of three open pull requests. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Raising Swift minimum version to 6.0:** Proposal to move the Swift implementation to version 6.0 to leverage native `Int128` support, which would simplify the implementation of high-precision Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **NumPy 2.0 requirement for Python strings:** Discussion on requiring NumPy 2.0+ for future Arrow releases to enable better conversion support for NumPy's new variable-width string types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)
