* **Apache Arrow 26.0.0 release:** The project announced the release of version 26.0.0, which includes over 330 resolved issues across the various language implementations and the format. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%2026.0.0%20-%20RC0)

* **Improving PyArrow modularity:** A proposal and proof-of-concept are underway to split PyArrow into smaller, modular wheels (e.g., `pyarrow-s3`) to reduce the monolithic package size and simplify installations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Improve%20modularity%20of%20PyArrow)

* **Dropping macOS Intel support:** Developers discussed dropping CI support and binary wheels for Intel-based Macs, citing Homebrew's deprecation of the platform and the very low percentage of active users on x86_64 macOS. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Drop%20macOS%20Intel%20support)

* **AI-generated contribution guidelines:** The community is establishing practices for handling AI-assisted pull requests, including a new "needs-author-engagement" label to flag PRs where the contributor fails to demonstrate understanding of their own code. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:AI-generated%20contributions)

* **IBM Db2 driver for ADBC:** IBM engineers proposed contributing a native C++ ADBC driver for Db2 (Linux, Unix, and Windows) to the project, expanding the ecosystem of native database connectors. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Request%20to%20contribute%20IBM%20Db2%20driver%20to%20arrow-adbc)

* **New range canonical extension types:** A vote is open to add `arrow.fixed_closedness_range` and `arrow.variable_closedness_range` extension types to the official format for better compatibility with interval data from pandas and PostgreSQL. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Fixed%20and%20variable%20closedness%20range%20canonical%20extension%20types)

* **Metadata for dictionary-encoded extensions:** Work is progressing on an IPC format change to allow dictionary-encoded fields to correctly preserve extension type metadata on their values, resolving a long-standing hole in the type model. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:IPC%20representation%20of%20dictionary-encoded%20extension%20types)

* **Flight SQL Substrait advertising:** A new proposal suggests using `SqlInfo` codes to allow Flight SQL servers to advertise which specific Substrait dialects they support, enabling better client-side validation of query plans. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Advertise%20supported%20Substrait%20dialect%20via%20SqlInfo)
