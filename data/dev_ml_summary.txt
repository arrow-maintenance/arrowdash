* **DuckDB ADBC extension donation:** Discussion on a proposal to donate a hand-coded ADBC client for DuckDB to the Arrow project to foster a neutral collaboration space. The thread includes a debate regarding governance and the trade-offs between AI-assisted and manual development. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ADBC%20Extension%20for%20DuckDB)

* **JSON representation of Arrow schemas:** Proposal to establish a canonical JSON format for Arrow schemas to improve ergonomics for REST APIs and metadata exchange. Feedback focused on reducing verbosity for common types and handling extension type metadata. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:JSON%20representation%20of%20Arrow%20schemas)

* **Deprecation of Tensor IPC messages:** Developers proposed deprecating experimental Tensor and SparseTensor IPC message types in favor of newer canonical extension types. This move aims to reduce maintenance overhead and address security validation complexities in the C++ implementation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Deprecate%20Tensor%20and%20SparseTensor%20messages)

* **Apache Arrow 25.0.0 release:** The community finalized the 25.0.0 release, featuring over 220 resolved issues. A planned 25.0.1 patch was also discussed to address critical PyArrow performance regressions for Spark 4.2 users. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **Conbench v2 benchmark tooling:** Updates on the modernization of the Conbench benchmarking platform, including a backend rewrite in Go and a new frontend using Vite and Svelte. The project aims to provide a more stable migration path while preserving existing database schemas. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Status%20of%20Arrow%20conbench%20data%20%2B%20conbench%20OSS%20project)

* **Variant and Parquet spec alignment:** Technical discussion regarding inconsistencies between the Arrow Variant extension and the Parquet shredding specification. Proposals were made to align allowed typed values and field nullability to ensure consistent round-tripping across implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **C Data Interface NUL byte handling:** A clarification on the C Data Interface spec regarding field names with embedded NUL bytes. Developers agreed that producers should validate names and error out rather than allowing consumers to encounter potential panics or invalid memory access. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **ADBC documentation overhaul:** Announcement of a major refresh for the ADBC documentation site, providing clearer guidance on driver sources. The updates better distinguish between ASF-maintained drivers and those provided by external vendors. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Documentation%20overhauled%20for%20ADBC)
