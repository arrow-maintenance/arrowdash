* **Windows on Arm support:** Microsoft proposed a support plan for win_arm64 PyArrow wheels, offering dedicated engineering resources and hardware for maintainers to ensure platform stability. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Tensor deprecation in IPC:** The community voted to informally deprecate Tensor and SparseTensor messages in the IPC protocol to reduce maintenance burden for features with low adoption. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Informal%20deprecation%20of%20Tensor%20and%20SparseTensor%20in%20IPC)

* **PR limits for non-committers:** To mitigate an uptick in AI-generated spam and stale contributions, a policy was discussed to limit non-committers to three concurrent open pull requests. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **BigDecimal canonical extension:** A vote for a canonical `arrow.big_decimal` extension type was paused to re-evaluate storage representation and its utility without native compute kernel support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **NumPy 2.0 requirement:** Developers discussed requiring NumPy 2.0 or newer in the next release to support the conversion of NumPy variable-width strings into native Arrow strings. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Requiring%20NumPy%202.0%20or%20newer%20in%20the%20next%20Arrow%20release)

* **Parquet FILE extension:** A proposal was introduced for an `arrow.parquet.file` extension type to align Arrow with the recently finalized FILE logical type in the Parquet specification. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **Lazy memory mapping for Parquet:** Discussion on using custom fault handling to lazily map Parquet columns to memory, allowing vectorized operations without explicit row group management. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Parquet%20C%20Python%20Lazy%20memory%20mapping)

* **Arrow-native language (ArxLang):** Introduction of Arx, an experimental programming language designed with Apache Arrow as its native foundation for data structures and runtime. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)
