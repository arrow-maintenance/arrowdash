* **PyArrow modularity and wheel splitting:** Proposal to break PyArrow into smaller, optional wheels (e.g., `pyarrow-s3`) to reduce the core package size and installation burden. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Improve%20modularity%20of%20PyArrow)

* **Dropping macOS Intel support:** Discussion on ending support for macOS Intel architectures due to Homebrew deprecations and low usage, which currently accounts for only 0.1% of PyArrow downloads. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Drop%20macOS%20Intel%20support)

* **Handling AI-generated contributions:** Community debate on establishing reviewer guidelines for low-quality AI PRs, including a proposal for a "needs-author-engagement" label to flag lack of developer interaction. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:AI-generated%20contributions)

* **Arrow 26.0.0 release:** Voting is underway for the version 26.0.0 release candidate, which includes over 330 resolved issues across the project components. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2026.0.0%20-%20RC0)

* **Range canonical extension types:** Formal vote to add `fixed_closedness_range` and `variable_closedness_range` to the Arrow specification to support bounded mathematical intervals. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Fixed%20and%20variable%20closedness%20range%20canonical%20extension%20types)

* **Arrow Rust 60.0.0 release:** The Rust implementation reached version 60.0.0, featuring new Parquet ALP encoding support and significant performance improvements for compute kernels. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2060.0.0%20RC1)

* **JSON representation of Arrow schemas:** Discussion on a standardized JSON format for Arrow schemas to help define data contracts and facilitate cross-language schema exchange. * **CSV date and time parsing improvements:** Push to merge long-standing changes that allow the CSV reader to use custom timestamp parsers as fallbacks for explicitly typed date and time columns.
