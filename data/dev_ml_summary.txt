* **Informal deprecation of Tensor and SparseTensor in IPC:** The community voted to deprecate Tensor and SparseTensor messages in the IPC protocol to simplify the specification, noting that C++ is currently the only complete implementation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Informal%20deprecation%20of%20Tensor%20and%20SparseTensor%20in%20IPC)

* **Arrow Rust 60.0.0 release:** This major release introduces support for Adaptive Lossless Floating-Point (ALP) encoding in Parquet, alongside significant performance improvements to kernels and the removal of panics from the codebase. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2060.0.0%20RC1)

* **Canonical extension type for FILE type:** A proposal is underway to define `arrow.parquet.file` as a canonical extension type to represent file-level references in-memory, aligning with recent changes to the Parquet specification. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **ArrowMetal 0.1.0 announcement:** A new project called ArrowMetal was introduced, providing Arrow compute kernels that run natively on Apple silicon GPUs using Metal and shared-storage memory to eliminate data transfer overhead. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20ArrowMetal%200.1.0%20Arrow%20compute%20on%20Apple%20silicon%20GPUs%20through%20Metal)

* **JSON representation of Arrow schemas:** Developers are discussing a standardized JSON format for Arrow schemas to help define data contracts and facilitate passing metadata between processes via configuration files. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20JSON%20representation%20of%20Arrow%20schemas)

* **Reviewer guidelines for AI-generated contributions:** The community is establishing procedures for reviewers to handle low-quality AI-generated pull requests, including the potential use of a "needs-author-engagement" label. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20AI-generated%20contributions)

* **Dropping macOS Intel support:** There is a proposal to drop CI support and official binaries for macOS Intel (x86_64) as Homebrew and Apple move away from the platform, though source builds may continue on a best-effort basis. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Drop%20macOS%20Intel%20support)

* **PyArrow modularity and multi-wheel installation:** A proof-of-concept is being developed to split PyArrow into multiple wheels (e.g., separating S3 support) to reduce the monolithic binary size on PyPI. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Improve%20modularity%20of%20PyArrow)

* **Arrow Go 18.8.0 release:** This release includes 283 commits across the Go libraries for Arrow, Flight, and Parquet, resolving issues with allocator alignment and compute registry aggregates. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Go%20Release%20Apache%20Arrow%20Go%2018.8.0%20RC1)
