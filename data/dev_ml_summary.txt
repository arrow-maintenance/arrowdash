* **Arrow 25.0.0 Release:** The community announced the release of Apache Arrow 25.0.0, which includes over 220 resolved issues and performance improvements across the ecosystem. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **JSON Representation of Arrow Schemas:** Discussion is underway regarding a canonical, human-readable JSON representation for schemas to simplify integration with REST APIs and ADBC metadata where binary IPC is less ergonomic. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:JSON%20representation%20of%20Arrow%20schemas)

* **Deprecating IPC Tensor Messages:** A proposal was made to deprecate legacy experimental IPC messages for Tensor and SparseTensor in favor of using fixed-shape and variable-shaped tensor extension types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Deprecate%20Tensor%20and%20SparseTensor%20messages%3F)

* **ADBC 24 Milestone:** The ADBC subproject released version 24, accompanied by a significant overhaul of the documentation to better clarify the source of various drivers for end-users. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Swift 6.0 Minimum Version Proposal:** Developers are discussing raising the minimum required Swift version to 6.0 to leverage native Int128 support, which is critical for implementing high-precision Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Variant Spec Inconsistency:** An inconsistency was identified between the Arrow Parquet Variant extension and the Parquet shredding specification regarding support for unsigned integer typed_value columns. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Nullability Semantics for Nested Types:** Community members are debating the intended meaning of the `nullable` flag for complex types, such as when a non-nullable child field exists within a nullable parent struct. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **C FFI Field Name Clarification:** Technical discussion on how the C Data Interface should handle embedded null bytes in UTF-8 field names to prevent potential crashes and ensure safe round-tripping between implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **Extended Range Timestamp Proposal:** A Parquet-level proposal was highlighted for storing full SQL-range timestamps at nanosecond precision, which may impact future Arrow implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:FYI%20Parquet%20proposal%20for%20extended%20range%20timestamp%20type)
