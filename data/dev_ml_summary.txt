* **Arrow CI cost reduction:** Proposal to cut GitHub Actions runner minutes by about 30-40% through workflow optimisations, prompted by shared-runner queue pressure across ASF projects. Discussion includes a recommendation to apply the same optimisations as Airflow. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Ideas%20to%20make%20Arrow%27s%20GitHub%20Actions%20CI%20lighter%20%28~30-40%25%20fewer%20runner%20minutes%29)

* **PyArrow 26.0.1 patch release:** Released on November 4 after RC1 passed. The release includes the fix for the statically linked Brotli CVE-2026-111497, which was requested by downstream users. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2026.0.1%20released) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Brotli%20CVE-2026-111497%20fix%20%28GH-55165%29%20in%2026.0.1)

* **Arrow Java 20.0.0 and release cadence:** Arrow Java 20.0.0 was released on November 21 and requires Java 17 or newer. A follow-up proposal to release Arrow Java at least quarterly, with the release managed by Jean-Baptiste Onofré, received broad support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20Java%2020.0.0%20Released) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Arrow%20Java%20regular%20release%20cadence)

* **Arrow Rust patch releases:** Several patch releases were approved in November, including 57.3.3, 58.4.2, 59.3.3, and 60.2.0. Each was published to crates.io after a vote. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2060.2.0%20RC1) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2059.3.3%20RC1)

* **ADBC 25 release:** The vote passed with six binding and one non-binding +1, and ADBC 25 was announced on October 27. Some packages were updated to 1.13.0, and R packages were accepted on CRAN after a delay. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20ADBC%2025%20Released) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:RESULT%20VOTE%20Release%20Apache%20Arrow%20ADBC%2025%20-%20RC2)

* **AI-generated contributions policy:** Maintainers proposed a PR cap, mandatory AI disclosure, auto-drafting of stale PRs, and a neutral "needs-author-engagement" label. A documentation PR was opened to codify the rule against AI-written review replies. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20AI-generated%20contributions)

* **Sovereign Tech Fund funds PyArrow:** The German Sovereign Tech Agency contracted about 1.9 FTE of work through 2026 and 2027. Work will cover type annotations, the issue backlog, AI-contribution tooling, and documentation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Announce%20The%20Sovereign%20Tech%20Fund%20invests%20in%20PyArrow)

* **GitHub pull_request_target restriction:** GitHub will restrict the pull_request_target trigger from December 2, with brownouts on November 9 and 16. Workflows across the Arrow repos need migrating, and the Boring Cyborg labeling bot has been enabled. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:pull_request_target%20trigger%20migration)

* **arrow.parquet.file canonical extension type:** A vote was opened to add a canonical extension type matching the Parquet FILE logical type. Some contributors argued Parquet-specific types should be defined by the Parquet project rather than in Arrow, so the vote may be paused. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Add%20arrow.parquet.file%20canonical%20extension%20type%20%28GH-51143%29) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Canonical%20Extension%20Type%20for%20FILE%20type)

* **Substrait dialect SqlInfo codes:** A vote proposes two Flight SQL SqlInfo codes, one for a Substrait dialect YAML and one for its content hash for client caching. The change is backward-compatible and has so far received only +1 votes. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20FlightSQL%20Add%20Substrait%20dialect%20SqlInfo%20codes)
