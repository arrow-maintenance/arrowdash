* **Parquet VARIANT field optionality:** Proposal to modify the Parquet format specification to allow the `value` field to be omitted, aligning the specification with Arrow's canonical extension and existing test cases. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Allow%20VARIANT%20value%20field%20to%20be%20omitted)

* **Deprecation of Tensor IPC messages:** Discussion on deprecating the experimental Tensor and SparseTensor IPC messages in favor of using canonical extension types, which offer better integration with existing Arrow APIs. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Deprecate%20Tensor%20and%20SparseTensor%20messages%3F)

* **JSON representation for Arrow schemas:** Debate on establishing a canonical, human-readable JSON format for Arrow schemas to facilitate easier use in REST APIs and ADBC metadata exchange. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:JSON%20representation%20of%20Arrow%20schemas)

* **Apache Arrow 25.0.0 release:** The community approved and released version 25.0.0, which includes over 220 resolved issues and performance improvements for Python `to_pylist` conversions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **C Data Interface field name clarification:** Technical discussion on how the C Data Interface should handle UTF-8 field names containing null bytes, with a preference for producers to error out to avoid C-string incompatibility. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **Apache Arrow ADBC 24 release:** Release of ADBC version 24 featuring independent versioning for subcomponents, an overhauled documentation site, and fixes for Windows JNI static linking. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Release%20Apache%20Arrow%20ADBC%2024%20-%20RC2)

* **Swift 6.0 minimum version proposal:** Proposal to increase the minimum required Swift version to 6.0 to utilize native `Int128` support, which is necessary for implementing Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Semantics of non-nullable nested fields:** Discussion regarding how the `nullable` flag should be interpreted for non-trivial types, such as child fields in a struct when the parent element is null. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Conbench benchmarking status:** Updates on the Conbench performance monitoring project, focusing on regression detection improvements and addressing recent backend timeout issues. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Status%20of%20Arrow%20conbench%20data%20+%20conbench%20OSS%20project)
