* **Arrow 25.0.0 and 25.0.1 releases:** The community released major version 25.0.0 followed by a 25.0.1 patch to address regressions in nested type conversions and Gandiva time zone handling. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2025.0.0%20released)

* **Nullability semantics for complex types:** Technical discussion regarding the meaning of the IPC `nullable` flag for fields within nested structures, such as null children in non-nullable parent structs. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Windows Arm64 support for PyArrow:** Proposal from Microsoft to provide dedicated engineering and hardware to enable win_arm64 builds, starting with a non-blocking nightly CI integration. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **ADBC 24 release:** A significant update for the Arrow Database Connectivity (ADBC) libraries was released, including improvements for the Go, Python, and Java drivers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20ADBC%2024%20Released)

* **Swift 6.0 upgrade proposal:** Discussion on raising the minimum Swift version to 6.0 to utilize native Int128 support, which is required for high-precision Decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **Limiting concurrent PRs for non-committers:** Proposal to limit the number of open pull requests from contributors without write access to manage the influx of stale and potentially AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **BigDecimal canonical extension type:** A formal vote was initiated for a new extension type to support variable-scale numeric data, though concerns remain regarding its internal representation. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Variant extension and Parquet inconsistency:** Developers identified discrepancies between the Arrow Variant extension spec and the Parquet shredding spec regarding support for unsigned integers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **nanoarrow 0.9.0 release:** The nanoarrow subproject released version 0.9.0, focusing on improved C/C++ helper functions and better integration with R and Python. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)
