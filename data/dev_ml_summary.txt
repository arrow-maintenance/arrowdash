* **Apache Arrow 25.0.0 release:** The community announced the availability of version 25.0.0, which includes over 200 resolved issues across multiple language implementations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2025.0.0%20released)

* **Nullability semantics for complex types:** A technical discussion on how the `nullable` flag should be interpreted for nested structures like structs and dictionary arrays in the IPC format. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Windows Arm64 support for PyArrow:** Microsoft proposed a formal plan to contribute and maintain Windows Arm64 support, including handling CI failures and consolidating the Windows build path. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Variant extension spec alignment:** Discussion on resolving inconsistencies between the Arrow Variant extension spec and the Parquet Shredding spec, particularly regarding unsigned integer support. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Format%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Proposal for BigDecimal Extension Type:** A vote was initiated to adopt a canonical extension type for variable-scale numeric data to improve interoperability with databases like PostgreSQL and Oracle. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Limiting concurrent PRs for non-committers:** Proposal to limit the number of open pull requests from non-committers to manage stale or AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Raising Swift minimum version to 6.0:** Proposal to upgrade the Swift implementation's requirements to leverage native Int128 support for high-precision decimal arithmetic. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Swift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **ADBC 24 and nanoarrow 0.9.0 releases:** Major updates were released for sub-projects, including ADBC version 24 and nanoarrow version 0.9.0. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20ADBC%2024%20Released) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)
