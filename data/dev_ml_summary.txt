* **Apache Arrow 25.0.0 release:** The community released version 25.0.0, resolving over 220 issues across the project including a fix for a Gandiva test failure and planning for subsequent performance patches in PyArrow. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.0%20-%20RC1)

* **JSON representation of Arrow schemas:** Discussion on standardizing a JSON format for Arrow schemas to improve human readability and interoperability for REST APIs and ADBC. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20JSON%20representation%20of%20Arrow%20schemas)

* **Semantics of non-nullable fields:** Technical debate regarding how implementations should interpret the `nullable` flag for complex types, particularly when parent and child nullability states conflict in nested structs. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Semantics%20of%20non-nullable%20fields%20with%20non-trivial%20types)

* **Swift 6.0 minimum version proposal:** Proposal to raise the minimum Swift version to 6.0 to leverage native `Int128` support, which is a prerequisite for implementing decimal types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSSwift%20Proposal%20to%20raise%20minimum%20Swift%20version%20to%206.0)

* **C Data Interface field name clarification:** Investigation into how the C FFI should handle field names containing embedded nul bytes, which are valid in Arrow but can cause issues in standard C string processing. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Spec%20clarification%20on%20field%20names)

* **Apache Arrow ADBC 24 release:** Announcement of the ADBC 24 release, featuring a major overhaul of the documentation site and updates across the C, Go, Java, Python, and Rust drivers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%20ADBC%2024%20-%20RC1)

* **nanoarrow 0.9.0 release:** Vote passed for the 0.9.0 release of nanoarrow, a lightweight implementation of Arrow, addressing 38 issues and introducing several new features. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)

* **Variant extension spec inconsistency:** Discussion on aligning the Arrow Variant extension specification with the Parquet Shredding spec to resolve discrepancies in how unsigned integers are handled. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)

* **Parquet extended range timestamp proposal:** Notification of a proposal in the Parquet community to store the full SQL range for nanosecond-level timestamps, potentially affecting future Arrow compatibility. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:FYI%20Parquet%20proposal%20for%20extended%20range%20timestamp%20type)
