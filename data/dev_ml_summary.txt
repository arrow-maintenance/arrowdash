* **nanoarrow 0.9.0 release:** Version 0.9.0 was released with 38 resolved issues and a focus on improved R and Python package stability. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20nanoarrow%200.9.0)

* **Arrow Rust releases:** The community released versions 59.2.0 and 59.3.0 of the Rust implementation, including various bug fixes and dependency updates. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20RUST%20Release%20Apache%20Arrow%20Rust%2059.3.0%20RC2)

* **Windows ARM64 support for PyArrow:** Microsoft proposed a plan to enable Windows ARM64 builds, offering to fund a dedicated engineer for maintenance and provide hardware for debugging. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Python%20CI%20win_arm64%20support%20for%20PyArrow%20proposed%20plan%20and%20commitment)

* **Apache Arrow 25.0.1 patch release:** A maintenance release addressed regression issues and improved performance for conversions on nested types. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Release%20Apache%20Arrow%2025.0.1%20-%20RC1)

* **Canonical BigDecimal Extension Type:** A proposal to standardize a variable-precision decimal type was paused to further explore requirements for compute kernels and RDBMS compatibility. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTE%20Format%20Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type)

* **Limiting concurrent PRs:** Discussion on capping non-committers to three concurrent open pull requests to manage the influx of stale or potentially AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **ArxLang introduction:** Developers introduced Arx, an experimental programming language designed with Apache Arrow as its native foundation for data types and runtime. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Lazy memory mapping for Parquet:** A proposal explores using custom page fault handling to lazily map Parquet columns into memory, enabling zero-copy NumPy operations over entire columns. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Parquet%20C%20Python%20Lazy%20memory%20mapping)
