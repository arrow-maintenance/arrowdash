* **Limit on concurrent PRs for non-committers:** Proposal to limit contributors without write access to 3 open pull requests to manage an influx of stale or AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Limit%20on%20concurrent%20open%20PRs%20for%20non-committers)

* **Deprecation of Tensor and SparseTensor in IPC:** The community voted to informally deprecate Tensor and SparseTensor messages in the IPC protocol, as they are rarely implemented outside of C++ and don't meet current format standards. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Informal%20deprecation%20of%20Tensor%20and%20SparseTensor%20in%20IPC)

* **Canonical BigDecimal Extension Type:** A proposal for an `arrow.big_decimal` type to handle arbitrary-precision numerics was discussed but ultimately paused to better evaluate performance requirements and ecosystem practices. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Proposal%20for%20Canonical%20BigDecimal%20Extension%20Type) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Status%20update%20on%20arrow.big_decimal%20extension%20proposal)

* **Arrow 25.0.1 Release:** The community finalized and announced the release of version 25.0.1, which includes several bug fixes and stability improvements. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Apache%20Arrow%2025.0.1%20released)

* **Introduction of ArxLang:** A new experimental programming language named Arx was introduced, which is designed to use Apache Arrow as its native foundation for data types and runtime operations. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ArxLang%20Arrow-native%20data%20types%20in%20a%20programming%20language)

* **Canonical Extension Type for FILE:** Discussion on adding a `arrow.parquet.file` extension type to align with the new Parquet FILE LogicalType for referencing external file data. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Canonical%20Extension%20Type%20for%20FILE%20type)

* **Lazy memory mapping for Parquet:** A proposal to use custom fault handling for lazy memory mapping of Parquet columns, allowing them to be treated as zero-copy NumPy arrays. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Lazy%20memory%20mapping)

* **New Committer Announcements:** The project welcomed several new committers this month, including Tadeja Kadunc, Zehua Zou, and Kosta Tarasov. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:New%20Arrow%20committer%20Tadeja%20Kadunc) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:New%20committer%20Zehua%20Zou) [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:New%20Arrow%20committer%20Kosta%20Tarasov)

* **Variant extension spec consistency:** Discussion on ensuring the Arrow Variant extension specification remains consistent with the Parquet shredding specification regarding unsupported types like unsigned integers. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Variant%20extension%20spec%20inconsistent%20with%20the%20Parquet%20shredding%20spec)
