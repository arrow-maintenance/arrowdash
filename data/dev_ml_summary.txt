* **Apache Arrow 26.0.0 release:** The community announced the release of version 26.0.0, resolving 337 issues and featuring significant updates across the C++, Python, and integration testing suites. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%2026.0.0%20released)

* **Sovereign Tech Fund investment in PyArrow:** The German government-backed Sovereign Tech Fund has contracted work for PyArrow to fund stalled research, improve documentation, and develop tooling to help maintainers manage AI-generated contributions. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:Announce%20The%20Sovereign%20Tech%20Fund%20invests%20in%20PyArrow)

* **GitHub Actions CI optimization:** A proposal to reduce Arrow's CI runner minutes by 30-40% suggests skipping redundant "Extra" workflows on merges and implementing stricter path filters to alleviate pressure on shared ASF runners. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Ideas%20to%20make%20Arrow's%20GitHub%20Actions%20CI%20lighter%20~30-40%25%20fewer%20runner%20minutes)

* **ADBC 25 release:** Release of version 25 for Arrow Database Connectivity (ADBC), providing independent version updates for the core manager and drivers across C++, Go, Java, Python, R, and Rust. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:ANNOUNCE%20Apache%20Arrow%20ADBC%2025%20Released)

* **Handling AI-generated contributions:** Discussion on managing the surge of AI PRs, with recommendations to make AI disclosure mandatory, auto-draft idle PRs, and adopt triage-gating similar to the pandas project. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20AI-generated%20contributions)

* **PyArrow modularity improvements:** Developers are discussing splitting PyArrow into smaller, modular packages to reduce the wheel size and avoid forcing users to install large, unnecessary dependencies. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSS%20Improve%20modularity%20of%20PyArrow)

* **IPC representation of dictionary-encoded extension types:** A proposal to add `custom_metadata` to `DictionaryEncoding` aims to fix a gap where IPC could not represent extension types that utilize dictionary encoding. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:IPC%20representation%20of%20dictionary-encoded%20extension%20types)

* **Range canonical extension types:** A vote was held to add `fixed_closedness_range` and `variable_closedness_range` as canonical extension types to support intervals used in Postgres and pandas. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:VOTEFormat%20Fixed%20and%20variable%20closedness%20range%20canonical%20extension%20types)

* **JSON representation of Arrow schemas:** Discussion on creating a standard JSON format for Arrow schemas to enable easier data contract definitions in configuration files and better interoperability with non-Arrow systems. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFormat%20JSON%20representation%20of%20Arrow%20schemas)

* **Substrait dialect advertising in Flight SQL:** Proposal to add new `SqlInfo` codes to Flight SQL so servers can advertise specific supported Substrait dialects, allowing clients to identify compatible plan features before execution. [Thread](https://lists.apache.org/list?dev@arrow.apache.org:lte=2M:DISCUSSFlightSQL%20Advertise%20supported%20Substrait%20dialect%20via%20SqlInfo)
